# Decentralized Identity (DID) Specification

## Overview

Arxia derives `did:arxia` identifiers from Ed25519 public keys, following the W3C DID syntax. No network access is needed to derive an identifier or to check it against a public key. DID documents, resolution and credentials are not implemented yet.

## DID Format

```
did:arxia:<base58(blake3(ed25519_pubkey_bytes))>
```

Example: `did:arxia:2DrjgbN7P3qRmjaHp2x5tQNKv94NwQEJhzRUmKXz4rKe`

## Generation

1. Generate Ed25519 keypair
2. Take raw public key bytes (32 bytes)
3. Compute Blake3 hash of public key bytes (32 bytes)
4. Base58-encode the hash
5. Prefix with `did:arxia:`

## DID Document Structure (planned, not generated by the code yet)

```json
{
  "@context": "https://www.w3.org/ns/did/v1",
  "id": "did:arxia:<identifier>",
  "verificationMethod": [{
    "id": "did:arxia:<identifier>#key-1",
    "type": "Ed25519VerificationKey2020",
    "controller": "did:arxia:<identifier>",
    "publicKeyMultibase": "z<base58_pubkey>"
  }],
  "authentication": ["did:arxia:<identifier>#key-1"]
}
```

## Checking an identifier offline

Checking a DID against a public key is O(1): compute blake3(pubkey),
base58-encode, compare. No registry lookup is needed. The DID is fully
derived from the public key.

## Verifiable Credentials (planned)

The design signs credentials with the holder's Ed25519 key so that any party that knows the issuer's public key can verify them offline. Credential issuance and verification, and DID document generation, are not implemented yet. The code today derives, parses and validates `did:arxia` identifiers, and the block lattice has a `Revoke` block type.

## Revocation

The block lattice has a REVOKE block type. In the design, once a REVOKE block is published for a credential hash, the credential is considered invalid, and revocation propagates through gossip. Credential issuance and verification are not implemented yet.
